# Feature Specification: 月別Orgファイルレイアウトと移行コンバーター

**Feature Branch**: `001-monthly-org-layout`

**Created**: 2026-08-02

**Status**: Draft

**Input**: User description: "<Org Directory>/mastodon/2026/08.org と言う形に保存するオプションと、既存のmastodon.orgからのコンバーターを作りたい。"

## Clarifications

### Session 2026-08-02

- Q: 変換時、既存の添付画像ファイルの実体は新しい年別 `.attach` ディレクトリへ「移動」と「コピー」のどちらにすべきですか？ → A: コピーする（元のファイルは削除しない）。加えて、コンバーターはコピーした添付ファイルの一覧を出力し、利用者が後で元ファイルを手動削除できるようにする。
- Q: 変換先に既に同名の月別ファイルが存在する場合、コンバーターは全体を中止すべきか、競合する月だけスキップして続行すべきか？ → A: 競合する月だけスキップし、競合しない月は変換を続行する。最後にスキップした月の一覧を警告として表示する。

### Session 2026-08-02（実装後の修正）

- 実装・実機検証の結果、当初FR-009で決めた `.attach/`（ID分割ディレクトリ構成）では、
  Emacs側のグローバル変数 `org-attach-id-dir` の設定（例: Doom Emacsが既定で
  `org-directory` 直下の `.attach/` に固定する）に依存してしまい、月別レイアウトの
  Orgファイルが `ORG_DIRECTORY` 直下にない場合に画像がインライン表示できない不具合が
  発覚した。→ 対応として、添付ディレクトリ名を `.attach` から `images` に変更し、
  ID分割をやめてフラット保存に変更、各月別ファイル先頭に
  `#+PROPERTY: ATTACH_DIR images/` を自動挿入する方式に修正（FR-009, FR-011を更新）。
  この変更は月別レイアウトのみが対象で、単一ファイルモードの保存形式・リンク形式は
  一切変更していない。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 月別ファイルへの分割保存 (Priority: P1)

利用者として、tootの記録が単一の巨大なOrgファイルに際限なく蓄積されていくのを避けたい。
そのため、`<Org Directory>/mastodon/YYYY/MM.org` のように年ディレクトリ・月ファイルへ
自動的に分割して保存するレイアウトオプションを使いたい。

**Why this priority**: 本機能の中心的価値。これが無ければユーザーストーリー2（コンバーター）も
成立しない。

**Independent Test**: 月別レイアウトを有効にした新規環境で同期を実行し、該当月のパスに
ファイルが作成され、tootが正しい日時見出しの下に時系列順で挿入されることを確認する。

**Acceptance Scenarios**:

1. **Given** 月別レイアウトが有効で対象ディレクトリにまだファイルが存在しない、**When** 2026年8月
   のtootを同期する、**Then** `<Org Directory>/mastodon/2026/08.org` が新規作成され、tootが
   記録される。
2. **Given** 同月内の既存ファイルにtootが記録済み、**When** 新たに同月の別のtootを同期する、
   **Then** 既存ファイルへ時系列順で追記され、重複や欠落が発生しない。
3. **Given** 月をまたいで同期を実行する、**When** 翌月分のtootを取得する、**Then** 新しい月の
   ファイル（例: `2026/09.org`）が新規作成され、前月分のファイルには影響しない。

---

### User Story 2 - 既存mastodon.orgからの一括変換 (Priority: P2)

既に単一の `mastodon.org` にtootを蓄積してきた利用者として、その内容を新しい月別レイアウトへ
一括変換したい。手作業でのコピー・分割を避け、既存の記録を失うことなく移行したい。

**Why this priority**: ユーザーストーリー1に依存する。新レイアウトへ移行する既存ユーザーに
とって必須だが、新規ユーザーには不要なため優先度はP2。

**Independent Test**: サンプルの既存 `mastodon.org` に対してコンバーターを実行し、生成された
月別ファイル群が元ファイルの全toot・引用ブロック・画像添付リンクを過不足なく含むことを確認する。

**Acceptance Scenarios**:

1. **Given** 複数年・複数月にまたがるtootを含む既存 `mastodon.org`、**When** コンバーターを
   実行する、**Then** 各tootの投稿年月に対応する `YYYY/MM.org` ファイルが作成され、元と同じ
   内容（本文・引用・添付リンク）が時系列順に含まれる。
2. **Given** 画像添付を含むtoot、**When** コンバーターを実行する、**Then** 変換後のファイルでも
   添付画像へのリンクが引き続き解決可能な状態を保つ。
3. **Given** 変換対象の元ファイル、**When** コンバーターを実行する、**Then** 元の `mastodon.org`
   は変更・削除されず、そのまま保持される。

---

### User Story 3 - 変換時の安全確認 (Priority: P3)

利用者として、コンバーターの誤操作によって既存の月別ファイルが上書きされ、記録済みのtootを
失うことがないようにしたい。

**Why this priority**: データ損失防止のための安全機構。中心機能（P1・P2）が動作した上での
追加の安全性向上のためP3。

**Independent Test**: 変換先に既に同名の月ファイルが存在する状態でコンバーターを実行し、
競合する月はスキップされて既存内容が保持されたまま、競合しない月は正常に変換され、
スキップされた月が一覧として警告表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 変換先ディレクトリに既に `2026/08.org` が存在する、**When** コンバーターを実行する、
   **Then** `2026/08.org` の既存内容は変更されずスキップされ、それ以外の競合しない月の
   ファイルは正常に変換される。
2. **Given** 変換対象に競合する月と競合しない月が混在する、**When** コンバーターの実行が
   完了する、**Then** 実行結果としてスキップされた月の一覧が利用者に警告表示される。

---

### Edge Cases

- 変換元 `mastodon.org` に、m2oが生成した見出し以外の手書きの自由記述行が含まれる場合、
  コンバーターはその内容も失わずに引き継がなければならない。
- ブースト引用ブロック（`#+BEGIN_QUOTE`〜`#+END_QUOTE`）を含むtootを変換する場合、
  引用ブロックの内容と元投稿者のクレジット表記を保ったまま移行する。
- 数百〜数千件規模のtootを含む大きな `mastodon.org` を変換する場合でも、処理が完了できる。
- 月別レイアウト運用中に、対象年のディレクトリが存在しない状態で新しい年のtootを初めて
  同期する場合、ディレクトリ自体も自動作成される。
- 同期処理が月別ファイルへの書き込み途中で失敗した場合、他の月のファイルや
  `state.json` の状態が不整合にならない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、tootの保存先として「単一ファイル（既存の挙動）」と「年ディレクトリ・
  月ファイル分割（`<Org Directory>/mastodon/YYYY/MM.org`）」の2つのレイアウトモードを、
  設定により選択できなければならない。
- **FR-002**: 月別レイアウトが有効な場合、システムは対象年のディレクトリおよび対象月の
  ファイルが存在しなければ自動的に作成しなければならない。
- **FR-003**: 月別レイアウトにおいても、システムは同一月内でtootを時系列順（古い順）に
  挿入しなければならず、再実行しても重複挿入や欠落を発生させてはならない。
- **FR-004**: システムは、既存の単一ファイル `mastodon.org` を入力として受け取り、
  投稿年月ごとに分割された月別レイアウトのファイル群を生成するコンバーター機能を
  提供しなければならない。
- **FR-005**: コンバーターは、通常のtoot本文に加え、ブースト引用ブロックや画像添付リンクを
  含む全てのtootを漏れなく変換後のファイルへ引き継がなければならない。
- **FR-006**: コンバーターは、変換先に同名の月別ファイルが既に存在する場合、その月の
  変換をスキップし既存内容を上書きしてはならない。競合しない他の月については変換を
  続行しなければならない。実行完了後、スキップした月の一覧を利用者に警告として
  表示しなければならない。
- **FR-007**: コンバーターは、変換元の `mastodon.org` ファイルを変更または削除しては
  ならない（非破壊的な変換であること）。
- **FR-008**: システムは、月別レイアウトで生成されるtoot見出しにおいても、元の単一ファイル
  レイアウトと同じ日時情報（日付・曜日・時刻）を保持しなければならない。
- **FR-009**: システムは、画像添付ファイルの実体を年ごとのディレクトリ
  （`<Org Directory>/mastodon/YYYY/images/`、ID分割なしのフラット構成）に配置し、
  各月別ファイルの先頭に `#+PROPERTY: ATTACH_DIR images/` を自動挿入することで、
  Emacs側のグローバルな`org-attach-id-dir`設定に依存せずリンクが解決可能な状態を
  保たなければならない（単一ファイルモードの `.attach/{id[:2]}/{id[2:]}/` 構成は
  この変更の対象外とし、従来通り維持する）。同一年内の全月別ファイル（`YYYY/MM.org`）
  が添付ディレクトリ（`YYYY/images/`）を共有するため、年単位でディレクトリごとの
  アーカイブ・移動が容易になる。
- **FR-010**: 月別ファイル内のtoot見出しの階層構造は、既存の単一ファイルレイアウトと
  同じ階層（`* YYYY` → `** YYYY-MM` → `*** YYYY-MM-DD` → `**** toot`）をそのまま維持
  しなければならない。月別ファイル単体をEmacsで開いた際にも、年・月の文脈が見出しから
  読み取れる状態を保つため。
- **FR-011**: コンバーターは、変換元の添付ファイル（`.attach/{id[:2]}/{id[2:]}/` の
  ID分割構成）を新しい年別 `images/` ディレクトリへID分割なしのフラット構成で
  「コピー」しなければならず、変換元の添付ファイルを変更・削除してはならない
  （FR-007と同様に非破壊的であること）。
- **FR-012**: コンバーターは、実行完了後にコピーした添付ファイルの一覧（変換元パスと
  変換先パスの対応）を利用者に表示しなければならない。これにより利用者は、変換結果を
  確認した上で任意に変換元の添付ファイルを手動削除できる。

### Key Entities

- **レイアウトモード**: tootの保存先の形式を表す設定値。「単一ファイル」または
  「年ディレクトリ・月ファイル分割」のいずれかを取る。
- **月別Orgファイル**: `<Org Directory>/mastodon/YYYY/MM.org` に対応し、その月に投稿された
  全tootの見出しツリーを保持するファイル。
- **移行コンバーター**: 既存の単一 `mastodon.org` ファイルを入力に、月別レイアウトの
  ファイル群を出力として生成する一回限りの変換処理。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 月別レイアウトを有効にした環境で同期を繰り返し実行しても、対象月のファイルに
  含まれるtoot件数が常に実際にMastodon上に存在するtoot件数と一致する（重複・欠落が0件）。
- **SC-002**: 既存の単一 `mastodon.org` ファイルをコンバーターで変換した場合、変換後の
  全月別ファイルに含まれるtoot件数の合計が、変換前の単一ファイルのtoot件数と完全に一致する。
- **SC-003**: 変換後、画像添付を含むtootについて、Org内のリンクを辿った際に画像ファイルが
  100%発見できる。
- **SC-004**: コンバーターの実行が原因で、既存の変換先ファイルが意図せず上書き・消失する
  事象が0件である。
- **SC-005**: コンバーター実行後、利用者は出力された一覧を見るだけで、コピーされた
  添付ファイルの変換元・変換先パスをすべて把握できる。

## Assumptions

- 「Org Directory」は既存の `ORG_FILE_PATH` の親ディレクトリ、または新たに専用の設定項目と
  して指定されるディレクトリのいずれかであり、具体的な設定方法（環境変数名など）は
  実装計画（Plan）フェーズで決定する。
- `mastodon` という固定のサブディレクトリ名は、ユーザーが示した例
  （`<Org Directory>/mastodon/2026/08.org`）の通りとする。
- コンバーターは `migrate_org.py` と同様、手動で一度だけ実行する単体スクリプトとして提供し、
  `m2o.py` の通常の同期処理には統合しない。
- コンバーター実行後は、通常の増分同期（`m2o.py`）がそのまま月別レイアウトに対して
  継続利用できる。
- toot日時の扱い（タイムゾーン変換等）は既存の単一ファイルレイアウトのロジックを踏襲する。
- 単一ファイルレイアウトから月別レイアウトへの変換は一方向のみをサポートし、逆方向
  （月別→単一ファイル）への変換は本機能のスコープ外とする。
